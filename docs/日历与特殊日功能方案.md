# 满伴成长树 · 日历与特殊日功能方案

> 状态：**已实现并验证通过（2026-11-15；2026-11-16 改版）** —— D1–D5 按推荐默认执行；可见性已简化为「公开 / 私有」，私有对孩子下发占位卡；日程支持跨天与时长双向计算（见 §4.1、§6.3、§14.1）。
> 输入：用户需求原话（2026-11-14）+ 现有代码现状（Money Jar / 满伴成长树，Vue3 + Fastify + SQLite）。

---

## 1. 一页摘要

在家长端和孩子端各新增一个「日历」页：

1. **日程（calendar events）**：仿飞书日程、按参与人组织。任何人都能建日程并指定参与人（某个孩子 / 自己 / 家长们），支持**跨天**与「开始 / 结束 / 时长」双向计算；月视图 + 日视图两步浏览。可见性只有两档：**公开 = 所有人可见**；**私有 = 全体家长可见，孩子之间只看到「私有日程」占位与时间**（创建者/参与孩子看完整）。
2. **特殊日（special days）**：家长专属。给某天起个名字（如「学习日」），支持**单天 / 每周几 / 每月几号 / 每年几月几号**四种重复规则，并可设置当天的积分效果：**获得翻倍、消耗减半**（倍数可自定义）。特殊日在两端日历上都有醒目横幅，孩子加分/兑换时自动套用并在流水里注明。

不动的部分：任务/积分/商城现有逻辑只是被「钩住」计算倍率，本身不改流程。

## 2. 需求还原与假设

| 用户原话 | 功能点 | 我补的假设（可推翻） |
|---|---|---|
| 双端做个日历 | 家长端 + 孩子端各一个日历页 | 放底部导航新页签「日历」 |
| 可以在日历增加日程 | 日程 CRUD | 双端都能建；孩子也能建（见 D4） |
| 指定孩子或者自己或者父母，按参与人 | 参与人多选（按飞书模式） | 参与人 = 全家任意成员；日程归属按「参与人」而非「创建人」 |
| 飞书日程的做法 | 表单字段、时间、全天、参与人头像展示 | v1 不做会议室/提醒推送/重复日程（见第 11 节「不做」） |
| 父母看到所有人的日程 | 家长端 = 全家日程聚合 | 含纯家长日程 |
| 孩子看到除父母以外的日程（兄弟姐妹） | 孩子端过滤规则 | 规则见第 4 节；孩子能看到「自己也参与」的混合日程 |
| 家长给特定日子设置节日（如学习日） | 特殊日管理，家长专属 | 特殊日是独立概念，不是日程（不进参与人逻辑） |
| 设置重复：每周几/每月几号/每年几号 | 特殊日重复规则 | 另支持「单天」；可选生效起止范围 |
| 获得积分翻倍 / 消耗积分减半 | 特殊日积分效果 | 效果倍数可自定义（1.5×、0.8×…）；作用范围见 D1/D2 |

## 3. 与飞书日程的对齐（按参与人）

飞书日程的核心心智：**一条日程 = 标题 + 时间 + 参与人列表**，视图上按「谁参与」聚合，不是按「谁创建」。落到满伴成长树：

- **参与人是身份不是归属**：日程不挂在某个人名下，而是一组参与人（家长 + 孩子任意组合）。列表里每个日程右侧/左侧显示参与人的生肖头像叠放（复用 `ZodiacAvatar`）。
- **月视图**：每格显示当天日程的彩色圆点/缩写条（按参与人着色），点格进入日视图。
- **日视图**：当天议程列表（全天置顶 → 按时间排序），底部「+ 新日程」。
- **新建表单**（飞书式从上到下）：标题 → 全天开关 + 时间段 → 参与人多选（头像 chips）→ 备注 → 保存即推送 WS 刷新两端。
- **编辑权限**：家长可改/删任何日程；孩子只能改/删自己创建的（见 D4）。

## 4. 角色与权限模型

单家庭模式（schema 注释明确无 family_id），`users.role` 只有 `parent` / `child`。

**可见性规则（2026-11-16 简化：只保留「公开 / 私有」两档）**

| 可见性 | 家长 | 孩子 |
|---|---|---|
| 公开（public） | 全部可见（完整） | **所有人可见**（完整；不用被邀请，也能看到） |
| 私有（private） | **全体家长可见（完整）** | 创建者与参与的孩子看完整；**其他孩子只看到「私有日程」占位卡**（保留日期/时间，隐藏标题 / 参与人 / 备注，没有编辑入口） |

> 旧的「家长公开（parents_only）」已移除：老库启动时自动转成 `private`。

**操作规则**

| 操作 | 家长 | 孩子 |
|---|---|---|
| 查看日历/日程 | ✅ 全部（含所有私有） | ✅ 公开全部 + 私有按上面规则（完整或占位） |
| 新建日程 | ✅ 参与人可选全家 | ✅ 参与人可选全家（含家长，如「明天开家长会」），但默认勾选自己 |
| 编辑/删除日程 | ✅ 任意 | ⚠️ 仅自己创建的 |
| 特殊日管理 | ✅ | ❌（只能看到横幅和效果） |

> 隐藏的孩子（`users.hidden = 1`）不出现在家长端的参与人选择器里；已有日程/特殊日数据不动。

### 4.1 私有日程（2026-11-14 追加；2026-11-16 按用户新口径简化）

日程 `visibility` 只有 `public` / `private`。私有日程的规则：

| 场景 | 规则 |
|---|---|
| 家长创建私有日程（无论参与人是谁） | **全体家长**都能看到完整内容；参与的孩子看完整；其他孩子只看到占位卡 |
| 孩子创建私有日程 | 参与人被后端锁定为自己；**全体家长**看完整；兄弟姐妹只看到占位卡 |
| 占位卡 | 只有「🔒 私有日程」+ 日期/时间（知道那天几点到几点有事），没有标题/备注/参与人/编辑入口；接口层面也不下发这些字段 |

- 表单两档：**公开 / 私有**（家长端、孩子端一致）。
- 私有提示：家长端「家长都可见；孩子之间只看到私有日程和时间」；孩子端「爸爸妈妈都能看到；兄弟姐妹只看到私有日程和时间」。
- 孩子选「私有」时，参与人 chip 锁定为自己（避免「选了兄弟姐妹却只看到占位」的困惑）。

## 6. 交互设计

### 6.1 月视图（两端一致，数据不同）

- 顶部：月份标题（‹ 2026年11月 ›）+ 右侧「特殊日」（家长端）或「🎉」图标（孩子端，只读列表）。
- 星期表头 一 ~ 日；日期块：数字 + 当天日程色点（最多 3 个 + 「+n」）+ 特殊日小角标（🎉）。
  - 2026-11-16 调整：特殊日 emoji 改为**紧跟日期数字右上角**（不再绝对定位到格子右上角——桌面端格子很宽，图标会离数字太远，看着不像一组）。
- 今天：mint 色圆环；选中日期：玻璃高亮底。
- 点日期 → 下方滑出**日视图**（弹层，不从月视图跳页，返回即收起）。

### 6.2 日视图（议程）

- **特殊日横幅**（签名元素，仅当天有特殊日时出现）：暖黄渐变玻璃条「🎉 今天是 学习日 · 获得积分 ×2」，孩子端在积分相关页面同步显示小角标。
- 日程列表：全天日程置顶；按时段排序；每张日程卡 = 色条 + 标题 + 时间 + 参与人生肖头像叠放（最多 4 个 + 数）。
- 空态：「这天还没有日程，点 + 安排一件事吧」。
- 右下角浮动「＋」→ 打开新建表单（预填选中日期）。

> 2026-11-16 按用户截图调整：新建入口改为**议程卡右上角的圆形「＋」**（固定在卡内，有日程时也在原位，不再悬浮遮挡内容）；「＋」用 flex 居中，修掉此前视觉偏下的问题；空态文案同步改为「点右上角 ＋ 安排一件事吧」。

### 6.3 新建/编辑日程（EventForm，飞书式）

1. **标题**（必填，≤50 字）
2. **日期范围**：开始日期 → 结束日期（默认同一天；**支持跨天**）
3. **全天**开关（默认关闭）+ 开始/结束时间：默认取**选中那天 09:00–10:00**；若选中的就是今天且已过 9 点，则从**当前时间的下一个整点**开始、持续 1 小时；23 点后默认 23:00 → 次日 00:00
4. **时长**：天 / 小时 / 分钟；与结束时间**双向计算**（改结束 → 时长自动变；改时长 → 结束自动变；改开始也保持时长不变）
5. **时间展示**：起止两端都写成「几月几日 几时几分」，例如 `11月16日 09:00 – 11月17日 11:30（1天2小时30分钟）`；表单里同一行左边开始、右边结束（窄屏自动分两行）
6. **参与人**：头像 chips 多选。家长视角分「家长」组和「孩子」组；孩子视角默认勾选自己，可加兄弟姐妹和家长
7. **谁能看见**：公开 / 私有（两档）
8. **备注**（选填，≤200 字）
9. 底部：保存 / （编辑时）删除——孩子看到的删除仅限自己创建的

保存 → WS `calendar_changed` 全家推送 → 两端日历静默刷新（沿用背包的刷新模式）。

### 6.4 特殊日管理（家长端专属）

入口：日历页右上「特殊日」→ 管理弹窗（现有列表 + 新建）。

新建表单：

1. **名称**（如「学习日」）+ **emoji**（预设一组：📚🎮🎉🎁🏆🚴等）
2. **重复规则**（单选）：
   - 单天：选具体日期
   - 每周：多选周几（一~日）
   - 每月：多选几号（1–31，29–31 在小月自动跳过）
   - 每年：选几月几日
3. **生效范围**：全家 / 指定孩子（头像多选）
4. **积分效果**（可组合）：
   - 获得：×2（可自定义 1.1–3.0）
   - 消耗：×0.5（可自定义 0.1–0.9）
   - 也可以只设其一（纯纪念性节日可以零效果）
5. **生效起止**（选填）：不填 = 永久

列表项显示：emoji 名称 + 规则摘要（「每周一三五」）+ 效果徽章 + 启用开关 + 删除。

### 6.5 特殊日效果的呈现

| 场景 | 呈现 |
|---|---|
| 两端日历月视图 | 日期块 🎉 角标 |
| 日视图 | 顶部横幅（名称 + 效果） |
| 家长端积分操作 | 加/扣分确认弹窗顶部提示「今天是 学习日，获得积分将 ×2」 |
| 孩子端积分变化 toast | 「+20 🌟（学习日 ×2 已生效 → 实得 +40）」 |
| 积分流水 | 备注后缀「（学习日 ×2）」，方便回溯 |
| 商城兑换确认 | 「今天是 学习日，消耗积分 ×0.5」 |

## 7. 视觉方向

完全延续现有设计语言（玻璃拟态 + 生肖头像 + 四色系统），不引入新体系：

- 参与人标识：`ZodiacAvatar` 叠放（现有组件直接复用）；日程色条从现有调色（mint/yellow/sky/red/peach）按**首个孩子参与人**的皮肤色取色，纯家长日程用 sky 蓝——孩子一眼能分「我们的事 / 大人的事」。
- 特殊日横幅是本功能的签名元素：暖黄渐变玻璃 + emoji 大号 + 效果徽章，其余部分保持安静。
- 月网格密度高，字号用 `--fs-2xs`，触控目标保持 ≥32px。

## 8. 数据模型（草案，按现有 schema 风格）

```sql
-- 日程（按参与人组织，飞书式）
CREATE TABLE IF NOT EXISTS calendar_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,                      -- ≤50 字
  event_date TEXT NOT NULL,                 -- 开始日期 YYYY-MM-DD
  end_date TEXT,                            -- 结束日期 YYYY-MM-DD；NULL = 同一天。支持跨天
  is_all_day INTEGER NOT NULL DEFAULT 0,
  start_time TEXT,                          -- 'HH:MM'，全天为 NULL
  end_time TEXT,                            -- 'HH:MM'，全天为 NULL
  note TEXT NOT NULL DEFAULT '',
  visibility TEXT NOT NULL DEFAULT 'public' CHECK (visibility IN ('public', 'private')),
  created_by INTEGER NOT NULL REFERENCES users(id),
  created_at INTEGER NOT NULL DEFAULT (unixepoch()),
  updated_at INTEGER
);

CREATE TABLE IF NOT EXISTS calendar_event_participants (
  event_id INTEGER NOT NULL REFERENCES calendar_events(id) ON DELETE CASCADE,
  user_id  INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  PRIMARY KEY (event_id, user_id)
);

CREATE INDEX IF NOT EXISTS idx_calendar_events_date ON calendar_events(event_date);

-- 特殊日（家长专属，带重复规则与积分效果）
CREATE TABLE IF NOT EXISTS special_days (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,                       -- 如 学习日
  emoji TEXT NOT NULL DEFAULT '🎉',
  rule_type TEXT NOT NULL CHECK (rule_type IN ('once','weekly','monthly','yearly')),
  once_date   TEXT,                         -- once: 'YYYY-MM-DD'
  weekdays    TEXT,                         -- weekly: JSON 数组，1=周一…7=周日
  month_days  TEXT,                         -- monthly: JSON 数组 [1..31]
  yearly_md   TEXT,                         -- yearly: 'MM-DD'
  range_start TEXT,                         -- 生效起始 YYYY-MM-DD（选填）
  range_end   TEXT,                         -- 生效结束（选填，含当天）
  scope       TEXT NOT NULL DEFAULT 'all' CHECK (scope IN ('all','custom')),
  effect_kind  TEXT CHECK (effect_kind IN ('earn','spend')),  -- NULL=纯纪念
  effect_value REAL,                        -- earn 倍率(>1) / spend 倍率(<1)；NULL=纯纪念
  enabled INTEGER NOT NULL DEFAULT 1,
  created_by INTEGER NOT NULL REFERENCES users(id),
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

CREATE TABLE IF NOT EXISTS special_day_targets (   -- scope='custom' 时的指定孩子
  special_day_id INTEGER NOT NULL REFERENCES special_days(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  PRIMARY KEY (special_day_id, user_id)
);
```

- 日程不存冗余参与人字段，列表查询 JOIN participants（家庭规模小，性能无忧）。
- 特殊日查询不做 SQL 展开重复：**取全部 enabled 行，在服务端 JS 展开到请求的月份区间**（每月切换只查一次，运算量可忽略）。

## 9. API 设计

统一挂在 `/api` 下，复用 `requireParent` 中间件与 zod 校验：

| 端点 | 方法 | 角色 | 说明 |
|---|---|---|---|
| `/calendar?from=&to=` | GET | 双端 | 区间内的日程（含参与人数组，孩子端服务端过滤）+ 区间内展开的特殊日 |
| `/calendar/events` | POST | 双端 | 新建（孩子端校验同上） |
| `/calendar/events/:id` | PATCH | 创建者/家长 | 编辑（孩子仅自己创建的） |
| `/calendar/events/:id` | DELETE | 创建者/家长 | 删除 |
| `/special-days` | GET | 家长 | 全量列表（管理用；孩子端不需要，区间数据随 /calendar 一起下发） |
| `/special-days` | POST | 家长 | 新建 |
| `/special-days/:id` | PATCH | 家长 | 编辑/启停 |
| `/special-days/:id` | DELETE | 家长 | 删除 |

**WS 事件**（沿用 `pushToAll` / `pushToUser` 模式）：`calendar_changed`、`special_days_changed`、`points_changed`（已有，payload 增加 `dayEffect` 字段：`{ name, emoji, earnMult?, spendMult? }`，供孩子端 toast）。

## 10. 积分钩子（核心机制）

新增服务端 helper（`server/src/services/dayEffect.ts`）：

```ts
/** 返回某孩子某天的积分效果：earn 取最大倍率、spend 取最小倍率，附来源 */
function dayEffectFor(childId: number, dateStr: string): {
  earnMult: number;   // 默认 1
  spendMult: number;  // 默认 1
  sources: { name: string; emoji: string; kind: string }[];
} | null
```

**接线点（共 5 处，只包一层计算，不改流程）**：

| 链路 | 现文件 | 应用 |
|---|---|---|
| 家长手动加分/扣分 | `routes/point-items.ts` | 正数 × earnMult（D1）；负数**不**套 spendMult（D2） |
| 临时任务奖励 | `routes/adhoc-tasks.ts`（审核通过加分处） | × earnMult |
| 周期任务打卡 | `routes/recurring-tasks.ts`（claim 通过加分处） | × earnMult |
| 商城兑换（礼物/道具） | `routes/exchange-requests.ts` | 所需积分 × spendMult（向下取整，最低 1 分） |
| 背包拿走返还 | `routes/backpacks.ts`（take 返还） | 返还属「获得」语义 → × earnMult |

- 应用后 `point_logs.note` 追加「（学习日 ×2）」；返回给前端的响应带 `dayEffect` 用于 toast。
- 家长端确认弹窗预提示当前效果（第 6.5 节），避免「怎么突然多给分」的困惑。
- 特殊日**只改倍率，不改规则**：限兑次数、每日上限等原逻辑不动。

## 11. 边界与规则

- **重叠特殊日**（同天多条匹配同一孩子）：earn 取最大倍率、spend 取最小倍率，横幅并列显示来源（D3）。
- **每周/每月规则的边界**：month_days 里的 29/30/31 在小月自动跳过；weekly 用 ISO 周一=1。
- **时区**：全部按服务器本地日期字符串（YYYY-MM-DD）比较，与现有 `growth_records` 同口径，不引入时区库。
- **v1 明确不做**（写死预期，避免范围膨胀）：日程重复规则、提醒推送、撤销/回收站、对外邀请、订阅同步。以上进「以后再说」清单。
  - 2026-11-16 更新：**跨天 / 多天日程已支持**（`end_date` + 时长双向计算），从「不做」清单移除。
- **删除成员**：users 删除 → 参与人/目标级联清理（FK CASCADE），日程本体保留（创建者没了仍显示，创建人显示「已注销」）。
- **老数据**：全新表，无迁移风险；`schema.sql` 建新库直通，老库靠 IF NOT EXISTS 补表。
- **性能**：月视图一次区间查询；特殊日 JS 展开 ≤ 数十行；无分页需求。

### 14.1 实施后的补充约定（2026-11-15 验证收尾时确认；2026-11-16 有更新）

| 事项 | 最终口径 | 原因 |
|---|---|---|
| 可见性档位（2026-11-16） | **只有公开 / 私有**；移除「家长公开」 | 用户要求简化：公开=所有人可见；私有=家长都可见、孩子只看占位 |
| 私有日程（2026-11-16） | 家长全可见；创建者/参与孩子看完整；其他孩子只看到 🔒 占位卡（保留日期/时间） | 用户明确：兄弟姐妹知道「几点到几点有事」即可，不显示详情 |
| 跨天与时长（2026-11-16） | `end_date` 支持跨天；表单「开始/结束/时长」双向计算 | 用户要求：几点到几点 + 持续时间，两个方向都能改 |
| 消耗倍率适用范围 | **仅商城/道具/许愿礼物**（`exchange_requests.type = product`）；**现金兑换不打折** | 现金比例固定（N 积分 = 1 元），打折等于「更少积分换同样的钱」，D2 只覆盖商城/道具 |
| 道具余额校验 | 用**当天折后价**判断，不用原价 | 否则三折当天会出现「折后付得起、原价被拦」 |
| 孩子端商城 | 显示折后价（原价划线）+ 暖黄提示条「今天是 xx，兑换消耗 ×0.5」；不再按原价预拦 | 方案 §6.5「兑换确认提示」；避免优惠被前端挡住 |
| 特殊日来源命名 | 流水后缀 / toast 里的节日名，取**等于聚合倍率的那一条** | 多条同类特殊日时，曾出现「按 ×0.3 扣、后缀写 ×0.5 的名字」 |
| 孩子私有日程 | 后端强制参与人 = 自己（父母仍可见） | 前端锁定之外再加一道，避免绕过表单把兄弟姐妹带进来 |
| 孩子端积分相关 toast | 任务审核、周期任务、兑换审批、背包返还、手动加减分，统一追加「（emoji 名称 ×倍率 已生效）」 | 避免「怎么突然多给分」的困惑 |
| 375px 导航 | 实测 6 页签放得下，**不降级** | 2026-11-15 实测：每项 ≥52px、文字无截断、无横向溢出 |
| 开源版兼容 | `users.family_id` / `notify_logs` 是商业扩展层对象，缺失时降级为单家庭，不再 500 | 任务提交曾因此在开源版直接失败 |
