注册页「用邀请码加入」提示改进 · 三方案

现状：底部只有一行 12px 的橙色小字「已经有家人建好了？用邀请码加入 →」，位置低、字小、不像能点，收到邀请码的家长大概率直接走了「创建家庭」。

方案 A（推荐）· 卡片式次入口
创建家庭
家庭名称
例如：我们家的满伴成长树
你的称呼
例如：妈妈
创建家庭
🎟️ 收到邀请码了？点这里加入 → 家人建好了家庭，你输码就能进来
思路：把那行小字升级成一张「看得见」的入口卡片：虚线描边 + 图标 + 两行文案，紧贴主按钮下方。
为什么推荐：改动最小（只动注册页底部一块）；视觉层级仍明确低于实心主按钮，不会误导新用户点错；「收到邀请码了？」直接对上这类用户的心理状态。
代价：无逻辑改动，纯样式。
方案 B · 分割线 + 描边次按钮
创建家庭
家庭名称
例如：我们家的满伴成长树
你的称呼
例如：妈妈
创建家庭
或
🎟️ 用邀请码加入家人的家庭
思路：经典的「—— 或 ——」分割线把两条路径摆成平等的两件事，下面配一个绿色描边次按钮。
优点：存在感最强，一眼两条路；样式通用，以后别的页面也能复用这套「主/次 + 或」版式。
代价：页面变长一点；描边按钮比方案 A 的卡片更容易被当成「另一个主要动作」，需要文案兜住（已有「创建家庭」在上，风险不大）。
方案 C · 顶部双 tab 切换
创建家庭
加入家庭
家庭名称
例如：我们家的满伴成长树
你的称呼
例如：妈妈
创建家庭
思路：把「创建 / 加入」做成页顶的两个切换标签，收邀请码的人一进来就能看到第二个 tab。
优点：定位最清晰，两条路径彻底对称；「加入家庭」页还能顺带放「粘贴邀请码」等能力。
代价：改动最大：要新建/合并页面、处理 tab 间状态与票据流转，测试面广；且 90% 的首用用户是「创建」，tab 会稀释主路径的注意力。
建议：等以后有「邀请码直接分享跳转」需求时再一起做。
